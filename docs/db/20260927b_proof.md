## Verdict

- **PASS.** No login loses a single row at a venue it may use.
- **Foreign rows only** are removed: 130 cost rows and 50 count lines across 11 logins.
- **No gain.** No login sees or writes anything new.
- **Writes still work.** Every venue login can still insert at every one of its own venues. None can insert anywhere else.
- **Nothing was applied.** Every request was `begin ... rollback`. No DDL and no writes were run. The runner refuses any write keyword. Production DDL is Peter's to run. The relayed "push live" does not cover it.

## How it was checked

- **Old text = live.** Each `oldUsing` and `oldCheck` in pairs.json matches `pg_policies` on live, character for character. Cmd, roles and permissive match too.
- **New text = migration.** Each `newUsing` and `newCheck` matches the `create policy` text in 20260927b once whitespace, `public.` and `AS` aliases are normalised.
- **Rollback = live.** The rollback file's 4 policies also match the live 26 Sep text.
- **Predicate pass.**
  - Runs as `postgres` (BYPASSRLS) with the login's JWT claims set.
  - Evaluates the old and the new text over every row of the table, FROM `public.<table>` with no alias.
  - Claims used: users `{"sub","role":"authenticated","aal":"aal2"}`; tills and ops tablets add `"is_anonymous":true` (read from auth.users); the anon key uses `{"role":"anon"}`.
- **Own venues** (the login may use them) = `user_accessible_locations()` plus the venue of any `devices` row with `device_uid` = that login, `bound_via` set and status `active` or `online`. For the booking_payments effective view this also includes active host stands (`waitlist_devices`), because "host stand read" is a real read path.
- **Live pass.**
  - Runs as the real role (`authenticated` or `anon`) with RLS on. Today that means the old 26 Sep policies.
  - The live counts must equal the old predicate AND the restrictive `second_step_fence`.
  - They matched for all 706 logins, so the predicate pass is a faithful model of the database.
- **Devices RLS pass.** The new "paired device read" runs a subquery on `devices`, and that table has its own RLS. So the subquery was also run as the till itself with RLS on. The result was then counted against booking_payments.
- **Synthetic write pass.**
  - Checks each WITH CHECK against one made-up row per venue: `(select v.id as location_id) as <table>`.
  - Covers all 13 real venues plus one venue id that does not exist (877f19df).
  - Nothing is written.
